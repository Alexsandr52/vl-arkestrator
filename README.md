# vl-arkestrator: «найди X и принеси» для G1 + Dex3

## Зачем

Оператор нажимает кнопку в веб-панели и говорит, например, «найди бутылку и принеси».
Оркестратор разбирает команду и выполняет задачу:

1. запоминает человека перед роботом;
2. ищет предмет поворотом на месте;
3. подходит к столу в позу, как при записи датасета;
4. берёт предмет нужной π0.5 VLA, проверяет захват и при промахе повторяет;
5. всегда сначала делает шаг назад от стола;
6. возвращается, находит того, кто дал команду, и протягивает предмет;
7. раскрывает кисть по «отпусти» и ждёт следующую команду.

Профили задач лежат в `profiles/`: бутылка, коробка и салфетка (выключена до появления
чекпойнта). Новая VLA подключается новым yaml-профилем, без правки кода.

Робот управляется кодом [GR00T-pickup-bottle](../unitree_proj/GR00T-pickup-bottle). Оттуда
берутся владелец DDS, стойки, тактильные проверки, IK, камера и ходьба. Архитектура, фазы и
решения описаны в [docs/architecture.md](docs/architecture.md).

## Установка (ноутбук, офлайн)

```bash
python3 -m venv .venv
.venv/bin/pip install pyyaml numpy pytest
```

На `g1-gpu` демон будет работать в клоне окружения `bottle-controller` (Python 3.10, PyYAML,
numpy, opencv), перцепция и π0.5 — в своих окружениях (P1).

## Запуск без робота

```bash
.venv/bin/python -m arkestrator --mock            # откроет панель http://127.0.0.1:8770/
.venv/bin/python -m arkestrator --mock --realtime 0   # симуляция без ожидания реального времени
```

Комната задаётся в `config/mock_world.example.yaml`: предметы, люди, «выученные» позы и
сценарий отказов (промахи, падение при переносе, перегрев). В панели:
1. «Начать сессию»;
2. команда текстом, например «принеси синюю бутылку»;
3. «Отпусти», когда робот протянет предмет.

Сессия завершается в два шага: «Подготовить отдачу рук», затем два флажка и «Подтвердить».
Первый Ctrl+C при активной сессии — это STOP: панель остаётся, чтобы отдать руки.

Голос в mock недоступен: Whisper появится в P1.

На g1-gpu панель открывается через туннель (localhost нужен браузеру для микрофона):

```bash
ssh -L 8770:127.0.0.1:8770 g1-gpu
```

## Проверки

```bash
.venv/bin/python -m pytest -q
```

Тесты используют mock и фейковые VLA-серверы, не трогают железо, GPU и сеть. Они проверяют:
- после успеха и после каждой восстановимой ошибки система возвращается в IDLE;
- STOP останавливает и базу, и движение рук; SAFE_HOLD не снимается ничем, кроме отдачи рук
  с одноразовым токеном и двумя подтверждениями;
- ходьба у стола держит коридор и курс, как `post_grasp_walk`;
- неподтверждённый захват опускается обратно на стол, а не роняется;
- у стола робот не поворачивается без шага назад;
- старое «отпусти» не используется повторно;
- контракты VLA проверяются строго, ответы отклоняются, а не исправляются.

## Настройки

- `config/session.example.yaml` → `config/session.yaml`: навигация, люди, проверка захвата, порт панели.
- `config/local.example.json` → `config/local.json`: пути к python и чекпойнтам по профилям, хосты, камеры.
- `config/taught/<профиль>.json`: где стоит предмет относительно робота в позе датасета. Записывается
  кнопкой Teach до сессии.

Эти файлы, датасеты, чекпойнты, `outputs/`, аудио и логи в Git не попадают.
